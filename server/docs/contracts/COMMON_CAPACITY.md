## Authority and activation

One canonical commercial capacity uses the existing entitlements/paid_extra_slots rules. A separately mapped claimed physical direct target occupies one seat; a real active account binding occupies one seat regardless of gateway count. No physical pairing, installation placeholder or second entitlement ledger is created. Scope/admission records store only protected activation and typed immutable ownership/order references.

`common_capacity.activate(connection, body, allowlist, dry_run=True)` validates the closed original manifest and protected allowlist, immutable stored manifest digest, complete correlated mapping proof, physical account/grant/fence/claim identity, device_index order, verified owner and current live capacity. Initial activation supports a complete direct-only manifest with no active mobile bindings. Stale, mixed, overcapacity or foreign/unverified inputs are rejected without reservations or victim selection. Exact activation replay retains all admissions, even after ordinary mobile admissions or capacity shrink; it creates no new seats, changes no order and resets nothing. A different activated scope requires a separate reviewed cutover.

Existing owner-only/non-symlink/bounded-file `delivery_stage.py` adds `--activate-capacity` with default dry-run; `--commit` is required to activate. Stage, claim scheduling and activation are separate mutually exclusive actions. Staging and successful claim alone reserve zero capacity; no payment/read/startup auto-activation. There is no new public identity/proof route or wire version. Operator runtime authorization remains a future gate.

## Counts, ranks and live deadlines

`occupied_count` counts retained direct seats plus ALL real active account bindings. An untracked imported mobile binding cannot be silently ignored for admission; it has no authorized mapped rank and receives no mapped grant until reviewed. Unactivated accounts use unchanged mobile bound_at/id ranks and counts. Activated order is direct seats in accepted device_index order, then authorized ordinary mobile admissions in durable append order. Revoke releases only that binding's incarnation; reactivation of the exact original account/installation pair appends anew and preserves binding generation rules. Active ranks compact over released mobile incarnations; retained direct seats always remain first.

`live_deadlines` is the shared live capacity authority: finite paid base ranks end at entitlement end; extra ranks use min(entitlement end, extra expiry descending), excluding expired extra slots. No slot UUID is assigned to a device. Trial/imported/nonfinite capacity retains stored limit/default two. `rank_capacity`, `binding_capacity` and `physical_capacity` expose identical rank/deadline logic. paid_limit reads this authority; mapped binding eligibility applies it for trial/imported as well as paid. Unmapped nonpaid behavior stays unchanged.

Capacity shrink does not erase occupancy, choose victims or automatically disable direct targets. First N ranks remain eligible and new admission is blocked while occupied count is at or above the effective limit. Payment refresh reads fresh extras, not stored device_limit for finite paid rights. Existing gateway.ensure_grant and queued apply dispatch use current_binding_paid_capacity and refuse an expired/ineligible mapped mobile rank before RPC. Existing extra lease maintenance uses the shared live mobile rank view rather than restarting mobile ranks at one.
