## 1. Дополнение к пользовательскому сценарию

### Первый запуск и обычное подключение

После установки APK пользователь не обязан получать персональную ссылку доступа или вручную вводить параметры сервера. Приложение уже содержит начальный штатный набор VK-хэшей, адреса и порты начального подключения, а также предусмотренные архитектурой данные проверки доверенного сервера.

Первый служебный выход к TERLIMO и последующее обновление каталога должны работать через VK-транспорт в условиях белых списков, без зависимости от доступности прямого HTTPS к TERLIMO. Этот ограниченный служебный доступ не равен полноценному VPN-доступу пользователя.

При каждом успешном соединении с сервером приложение получает актуальный штатный набор VK-хэшей и сохраняет его для следующих подключений. Ошибка получения или проверки обновления не уничтожает последний корректно сохранённый набор. Не требуется переустанавливать APK при обычном обновлении хэшей сервером.

Порядок первого часа VPN, регистрации Telegram, пробного периода и оплаты остаётся согласно действующему решению о первом часе: восстановление транспорта не активирует trial и не продлевает доступ.

### Аварийное восстановление через свою ссылку VK

Если подключиться со штатными сохранёнными вариантами не удалось, приложение предлагает восстановление через пользовательскую ссылку. Эта возможность доступна также в настройках. Это крайний резерв, а не обязательный шаг обычного onboarding.

1. Пользователь открывает пункт «Восстановить подключение через VK».
2. Короткая инструкция предлагает открыть VK, создать групповой звонок, скопировать ссылку и вставить её в поле приложения. Точные шаги интерфейса VK уточняются при проверке; заранее не заявляется, что любая ссылка пригодна.
3. Поле принимает ссылку на звонок целиком либо VK-хэш. Приложение извлекает и проверяет формат, объясняет ошибку ввода без показа внутренних секретов.
4. Приложение использует пользовательский хэш для VK-транспорта, сохраняя известные ему доверенные адрес, порты и параметры идентификации сервера TERLIMO. Пользователю не нужно настраивать сервер.
5. После успешного соединения сервер обрабатывает обычные авторизованные служебные запросы: состояние доступа, каталог и актуальный штатный набор хэшей. Приложение сохраняет полученные штатные данные и возвращается к обычному порядку подключения. Не вводить отдельный обязательный разрыв уже работающего соединения только ради обновления списка.
6. При неудаче пользователь может исправить или удалить свою ссылку; штатный набор и учётные данные не теряются. Пользовательская ссылка хранится отдельно от серверного набора и не загружается в общий каталог для других пользователей.

Не утверждать в интерфейсе «хэши истекли» по одному факту неудачи: возможны отсутствие сети, ошибка VK или недоступность сервера. Пример сообщения: «Не удалось подключиться. Можно попробовать восстановить доступ через свою ссылку на звонок VK». Ссылка не гарантирует успех при любой причине сбоя.

## 2. Дополнение к целевой архитектуре

### Начальная конфигурация и обновляемые данные

В APK поставляется неперсональная начальная конфигурация: штатные VK-хэши, адреса/порты начальных узлов TERLIMO и предусмотренные действующей архитектурой доверенные идентификаторы/ключи проверки. Встраивание начальных параметров не разрешает включать административные, платёжные или персональные пользовательские секреты.

Разделяются три источника: встроенный начальный набор; актуальный штатный набор, полученный от доверенного сервера и сохранённый приложением; отдельный пользовательский аварийный хэш. Пользовательский ввод меняет только источник транспортных VK-данных и не меняет адресата, доверие к серверу, идентичность установки или коммерческие права.

Обновление штатного набора принимается только по штатному доверенному служебному пути. Сохраняются существующие проверки принадлежности данных узлу, актуальности ответа и защиты от запоздалой записи. Ошибка/повреждённый ответ не затирает последний корректный набор. Начальные адреса не ограничивают динамический каталог одним или двумя шлюзами: требования произвольного числа шлюзов и переключения любого на любой сохраняются.

### Разделение транспорта и прав доступа

Путь: клиент использует VK-хэш для получения VK TURN-параметров → через VK-транспорт обращается к отдельно заданному узлу TERLIMO → проходит предусмотренную проверку сервера и авторизацию служебной операции → получает данные Backend. Служебные запросы должны быть достижимы без активного пользовательского data-grant; они не превращаются в произвольный бесплатный интернет-прокси.

Узел TERLIMO не должен требовать предварительно записывать пользовательский VK-хэш в свою конфигурацию или вступать в тот же звонок. Адресат определяется конфигурацией соединения, а право выдачи каталога/подписки — штатными installation/session/PoP/scopes. VK-хэш не является подтверждением подписки. Центральный Backend остаётся источником прав и каталога, а шлюз не получает самостоятельной бизнес-логики.

Ссылки/хэши и временные VK credentials не выводятся в общедоступные логи, отчёты и диагностику. Для recovery не создаются новые постоянные службы или отдельный Backend.

### Границы подтверждения и будущая приёмка

По исходникам транспорта 10011f7 подтверждено: hash используется клиентским GetCreds для VK TURN, peer задаётся отдельно, серверный admission не сверяет client hash. Контрактная проверка также не выявила hash как входной параметр session/access-sync. Это не доказывает готовность Android UI, managed adapter или реального соединения через конкретного оператора.

Живой прогон с пользовательской ссылкой, отсутствующей в конфигурации сервера, пока не выполнен. Павел предоставит её позднее; тест не запускается в рамках текущего изменения документов. Требование утверждено сейчас, статус фактической возможности не подменяется PASS.

При возобновлении соответствующего этапа достаточно проверить:
- чистую установку и получение служебных данных через VK при недоступном прямом HTTPS к TERLIMO;
- получение/сохранение актуального штатного набора и его использование после перезапуска;
- отказ штатных хэшей, ручной ввод отдельной действующей VK-ссылки и соединение с тем же узлом без изменения серверной конфигурации;
- получение актуальных штатных данных через восстановленный путь с сохранением проверки сервера, установки и прав доступа;
- неверный/неработающий пользовательский ввод и сетевой сбой без потери последнего корректного набора и без ложного изменения срока подписки.

Недоступность всех встроенных адресов/портов или самого сервера не устраняется заменой VK-хэша. Если адресная проверка покажет несовместимость механизма с фактическим транспортом, результат докладывается владельцу для выбора альтернативы; готовность не объявляется и архитектура молча не подменяется.
