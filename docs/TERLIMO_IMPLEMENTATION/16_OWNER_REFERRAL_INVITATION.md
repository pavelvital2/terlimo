## Согласованный пользовательский сценарий

1. Пользователь нажимает в TERLIMO «Пригласить друга» и отправляет приглашение через MAX, VK, Telegram или другой канал.
2. Приглашение содержит ссылку и короткий код, позволяющий определить пригласившего.
3. Если приложение уже установлено, ссылка открывает его и передаёт код приглашения.
4. Если приложения нет, ссылка ведёт на страницу нашего домена с инструкцией установки. После установки друг открывает приложение и вводит код. Автоматический перенос кода через установку пока не обещается.
5. Регистрация проходит в приложении по штатному пользовательскому сценарию. Приложение передаёт код backend через служебное подключение; backend связывает приглашённого пользователя с пригласившим.
6. В режиме белых списков страница домена может быть недоступна, поэтому переход на неё не обязателен: друг может получить приложение отдельно, например через MAX/VK, установить и ввести код внутри приложения.

Основа механизма — код, принимаемый приложением. Ссылка — удобный способ передачи кода, а не обязательный внешний этап регистрации.

## Архитектурные следствия

- Поддержать получение кода при открытии ссылки и ручной ввод внутри приложения.
- Сохранить работоспособность ввода/передачи кода через штатный служебный VK-транспорт без зависимости от прямого доступа к странице домена.
- Связь приглашения с пользователем хранит центральный backend. Реферальный код сам по себе не является ключом доступа или подтверждением оплаченной подписки.
- Конкретный формат ссылки/кода, обработчики для платформ и момент привязки в существующем процессе регистрации уточнить при проектировании; не заменять ими утверждённую авторизацию.

## Будущая проверка

- Открытие приглашения с установленным приложением и получение корректного кода.

### Приглашённый

- Получает приглашение; установленное приложение принимает код из ссылки. Без приложения можно открыть страницу установки либо получить приложение отдельно и ввести код вручную.

### Ошибки и ограничения

Некорректный/неактивный код, временная недоступность сервера и уже существующая привязка обрабатываются отдельными понятными состояниями. Возможность смены привязки, срок ввода кода и участие ранее зарегистрированных пользователей ещё требуют бизнес-решения. Реализация не должна молча выбирать эти правила.

Ввод кода и самостоятельная установка должны работать без доступного сайта; автоматический перенос кода через установку не обещан. Начисления и их отображение реализуются после согласования размеров, события выдачи и правил применения. Упоминание дней в обсуждении не исключает другой отдельно согласованный вид бонуса.
