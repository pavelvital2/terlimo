## Согласованный пользовательский сценарий

1. Пользователь нажимает в TERLIMO «Пригласить друга» и отправляет приглашение через MAX, VK, Telegram или другой канал.
2. Приглашение содержит ссылку и короткий код, позволяющий определить пригласившего.
3. Если приложение уже установлено, ссылка открывает его и передаёт код приглашения.
4. Если приложения нет, ссылка ведёт на страницу нашего домена с инструкцией установки. После установки друг открывает приложение и вводит код. Автоматический перенос кода через установку пока не обещается.
5. Регистрация проходит в приложении по штатному пользовательскому сценарию. Приложение передаёт код backend через служебное подключение; backend связывает приглашённого пользователя с пригласившим.
6. В режиме белых списков страница домена может быть недоступна, поэтому переход на неё не обязателен: друг может получить приложение отдельно, например через MAX/VK, установить и ввести код внутри приложения.

Основа механизма — код, принимаемый приложением. Ссылка — удобный способ передачи кода, а не обязательный внешний этап регистрации.

- Поддержать получение кода при открытии ссылки и ручной ввод внутри приложения.

## Решение владельца03.10: отдельная вкладка и выдача кода после регистрации

Павел требует отдельную вкладку «Реферальная программа» в приложении, с узнаваемой пиктограммой подарочной коробки с бантом/лентой. Во вкладке подробно описываются условия и выгода обеих сторон и показывается собственный уникальный код пользователя. Это новое указание заменяет прежнюю формулировку «не требует новой основной вкладки» в раннем описании.

Собственный код появляется только после первой подтверждённой регистрации: сервер выдаёт/возвращает его зарегистрированному аккаунту, приложение показывает код и действия копирования/передачи. Само открытие приложения, скачивание APK и получение бесплатного часа не создают права на собственный реферальный код. Код приглашения друга, который новый пользователь вводит перед регистрацией, и собственный код после регистрации — разные сущности.

Рекомендация root к реализации: один постоянный серверный код на аккаунт, одинаковый в приложении/боте/на сайте и на всех привязанных устройствах; повторная регистрация той же учётной записи, переустановка или повторный запрос возвращают существующий код, не выдают другой и не создают повторные бонусы. При уже существующем коде рабочего аккаунта следует переиспользовать его. Это соответствует ранее выбранной единой программе аккаунта.

До регистрации рекомендуется показывать условия программы и понятное объяснение «Ваш код появится после регистрации» с переходом к штатной регистрации; не показывать вымышленный/локально сгенерированный код. После регистрации — свой код, копирование/передача и одинаковые актуальные условия.

Навигация: требование отдельной вкладки принято, но окончательное место/замена среди ранее согласованных пяти вкладок ещё не выбраны. Не добавлять шестую и не удалять существующую функцию молча; распределение по вкладкам остаётся отдельным обсуждением перед дизайном. Сейчас записать требование, не запускать UI/дизайн/разработку на паузе.
